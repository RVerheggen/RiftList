## Design Specificity Verdict

### LLM assessment

RiftList feels authored for card trading. The warm paper workspace, deep collector-board preview, controlled orange signal color, editorial WANTED typography, physical board shadow, quantity badges, and card-art-forward composition support the product rather than decorating a generic form. ## Overall Impression

The front page is already a strong, polished Operate-mode tool. Its best quality is that the actual task is unmistakable and the share artifact feels like a real collector object. The largest opportunity is to strengthen trust at the moment the app interprets imperfect input.

## What's Working

1. **The task is immediately legible.** The headline, textarea, examples, Match cards button, and live preview form a direct paste-to-share path without marketing detours.
2. **The visual language belongs to RiftList.** The warm ivory editor and deep forest wanted board create a memorable collector-desk composition while letting card artwork carry the saturated color.
3. **Recovery for unmatched lines is unusually good.** The Needs a look panel preserves the original line, explains the problem, and offers direct card suggestions instead of silently dropping input.

## Cognitive Load and Emotional Journey

The cognitive-load checklist has one failure out of eight: progressive disclosure. The helper examples and Accepted formats block communicate overlapping information at the same time. All decision points remain at four or fewer visible options, so overall cognitive load is low.

The emotional journey starts reassuringly, peaks when recognizable card art appears, and ends well with clear copy, share, and save actions plus toast confirmation. The valley is confidence: an automatically accepted typo match looks nearly identical to an exact match, so users may feel reassured before they have actually verified the interpretation.

## Priority Issues

### [P1] Automatic fuzzy matches do not demand enough review

**Why it matters:** A typo match is placed directly in the wanted board and share output. The small `Matched from` note and toolbar count are easy to miss, especially on a phone. A wrong card in a trade message damages trust more than an unmatched line.

**Fix:** Treat fuzzy matches as review items. Require an explicit accept action before export, or place a prominent confidence marker on the card and disable sharing until each uncertain match is confirmed.

**Suggested command:** `$impeccable harden`

### [P1] Clear can erase the persisted working list without recovery

**Why it matters:** Clear acts immediately and local storage mirrors the empty value. An accidental thumb tap can remove a long wanted list with no visible way back.

**Fix:** Add a short-lived Undo toast that restores the previous input. Confirmation would work, but undo is faster and better suited to this low-friction tool.

**Suggested command:** `$impeccable harden`

### [P2] Grid metadata is below comfortable phone reading size

**Why it matters:** The mobile grid uses 10px card names and 8px metadata while retaining three columns. Artwork remains recognizable, but names, codes, and variants become difficult to verify before sharing.

**Fix:** Preserve three-column visual scanning but reveal a readable selected-card summary on tap, or use two columns below the narrowest breakpoint. Keep List as the clearly recommended verification mode on small screens.

**Suggested command:** `$impeccable adapt`

### [P2] Format guidance is duplicated in the primary mobile path

**Why it matters:** The inline Formats examples and Accepted formats glossary overlap. On a phone this adds vertical distance between the input action and the preview without adding a new decision.

**Fix:** Keep one compact example row visible and move aliases and card-code details into a disclosure labeled Accepted formats.

**Suggested command:** `$impeccable distill`

### [P2] Catalog recovery copy exposes an implementation detail

**Why it matters:** `public/data/cards.json` is meaningful to the maintainer, not a GitHub Pages visitor. If the catalog fails, the interface is blocked and the suggested check is not actionable for the user.

**Fix:** Tell visitors to reload, try again online, or report the problem. Keep the file path in console diagnostics only.

**Suggested command:** `$impeccable clarify`

## Persona Red Flags

### Riley, deliberate stress tester

- A fuzzy match is accepted into the final artifact without a separate confirmation state.
- Clear followed by refresh permanently preserves the empty list, with no restore path.
- The catalog error presents a repository path instead of a visitor recovery action.

### Casey, distracted mobile user

- The three-column grid makes verification text very small on narrow phones.
- Clear sits beside formatting help and acts immediately, making an accidental thumb tap costly.
- Duplicate format guidance lengthens the route from paste to preview, although automatic scrolling after Match cards helps.

### Jordan, first-time trader

- Exact and fuzzy matches look too similar, so Jordan may not understand which cards still need judgment.
- The meaning of AA, Sig, and ON is explained clearly, but the same area competes with a second set of examples.
- The main action and export actions are well labeled, so basic task discovery remains strong.

## Minor Observations

- The Ctrl or Command plus Enter shortcut is useful but invisible. A compact hint could reward repeat users.
- `aria-live="polite"` wraps the entire wanted board, which may produce verbose announcements when several cards change at once.
- The source note is appropriately restrained and reinforces the offline story.
- Grid, List, and Compact are clear labels, and the selected state follows familiar segmented-control conventions.

## Questions to Consider

1. Should an uncertain match be allowed into a shareable artifact before the trader explicitly approves it?
2. Is three-column phone density more important than reading names and variants without switching layouts?
3. Could format help become a single concise example plus an optional glossary?
